这份 **30 天 Flask 从零基础到登录表单实战** 课程设计，按“环境与基础 → 路由与模板 → 表单与数据 → 登录认证与实战”四个阶段推进，每天聚焦 1 个核心主题（建议每天 1～2 小时：30% 原理 + 70% 动手敲代码）。

  

### 第一阶段：环境搭建与 Flask 核心入门（第 1～6 天）

- **第 1 天：Python 基础回顾与虚拟环境**
    
    - 复习字典、列表、装饰器、函数参数与模块导入。
        
    - 学习使用 `venv` 创建并激活隔离虚拟环境，理解依赖管理意义。
        
- **第 2 天：安装 Flask 与第一个 Web 应用**
    
    - 安装 `flask`，编写最小可用应用 `app.py`（`Hello, Flask!`）。
        
    - 理解 WSGI 与开发服务器启动参数（`debug=True`、端口与主机配置）。
        
- **第 3 天：动态路由与 URL 变量**
    
    - 掌握 `@app.route()` 绑定路径，使用 `<int:user_id>`、`<string:username>`、`<path:...>` 提取 URL 参数。
        
    - 了解 `url_for()` 反向生成 URL，避免硬编码路径。
        
- **第 4 天：HTTP 请求方法与 `request` 对象**
    
    - 区分 `GET` 与 `POST` 请求场景。
        
    - 使用 `request.args` 读取查询参数、`request.form` 读取表单数据、`request.headers` 查看请求头。
        
- **第 5 天：响应构造、状态码与重定向**
    
    - 返回文本、HTML、元组 `(body, status_code)` 及 JSON（`jsonify`）。
        
    - 掌握 `redirect(url_for(...))` 跳转与 `404` / `500` 自定义错误页面。
        
- **第 6 天：阶段小练习——个人名片与多页导航**
    
    - 搭建包含首页、关于页、动态用户主页和错误页的多路由小站。
        

### 第二阶段：Jinja2 模板引擎与静态资源（第 7～12 天）

- **第 7 天：Jinja2 变量、过滤器与控制结构**
    
    - 在 `render_template()` 中向模板传参。
        
    - 掌握 `{% if %}`、`{% for %}` 循环与常用过滤器（`default`、`length`、`escape` 等）。
        
- **第 8 天：模板继承与宏（Macros）**
    
    - 设计 `base.html` 骨架，使用 `{% block %}` 复用头部、导航栏与页脚。
        
    - 使用 `{% macro %}` 封装可复用的 UI 组件（如警告提示框、表单字段）。
        
- **第 9 天：静态文件管理与前端基础接入**
    
    - 规范放置 `static/css`、`static/js`、`static/images`，通过 `url_for('static', filename=...)` 引入。
        
    - 引入轻量 CSS 框架（如 Bootstrap）美化页面排版。
        
- **第 10 天：消息闪现（Flash Messages）**
    
    - 配置 `app.secret_key`，使用 `flash()` 发送一次性提示并在模板中渲染成功/错误提醒。
        
- **第 11 天：模块化组织——蓝图（Blueprint）入门**
    
    - 拆分单文件 `app.py`，按功能划分 `auth`、`main` 等蓝图，理解大型项目的目录结构。
        
- **第 12 天：阶段小练习——带导航与提示条的内容展示页**
    
    - 完成多页面模板继承、静态样式加载与操作反馈提示。
        

### 第三阶段：表单处理、数据校验与状态保持（第 13～20 天）

- **第 13 天：原生 HTML 表单与服务端接收**
    
    - 编写 `<form method="POST" action="...">`，理解 `name` 属性与 `request.form.get()` 的安全取值方式。
        
- **第 14 天：Flask-WTF 与表单类定义**
    
    - 安装并配置 `Flask-WTF`，将表单字段抽象为 Python 类（`StringField`、`PasswordField`、`SubmitField`）。
        
- **第 15 天：内置校验器与错误回显**
    
    - 使用 `DataRequired`、`Email`、`Length`、`EqualTo` 校验用户输入。
        
    - 在模板中遍历 `form.errors` 显示字段级报错信息，保留合法输入值。
        
- **第 16 天：CSRF 防护机制**
    
    - 理解跨站请求伪造原理，掌握 `{{ form.hidden_tag() }}` 与 `SECRET_KEY` 的配合机制。
        
- **第 17 天：Session 会话机制详解**
    
    - 理解 HTTP 无状态特性与 Cookie/Session 的工作流程。
        
    - 使用 `session['user']` 存储和清除用户会话状态。
        
- **第 18 天：密码安全存储与哈希加密**
    
    - 严禁明文存密码；使用 `werkzeug.security` 中的 `generate_password_hash()` 与 `check_password_hash()`。
        
- **第 19 天：SQLite 与 SQLAlchemy 基础**
    
    - 定义 `User` 模型（`id`、`username`、`email`、`password_hash`），完成建表、新增用户与按用户名/邮箱查询。
        
- **第 20 天：阶段小练习——用户注册表单与数据库落库**
    
    - 实现带邮箱/密码强度校验与重复账号检测的注册流程。
        

### 第四阶段：登录表单深度专题与综合实战（第 21～30 天）

- **第 21 天：登录表单结构与交互细节设计**
    
    - 设计包含“用户名/邮箱”、“密码”、“记住我（Remember Me）”与“提交按钮”的登录表单。
        
    - 考虑自动聚焦、密码显示/隐藏切换与回车提交体验。
        
- **第 22 天：登录认证核心逻辑编写**
    
    - 接收表单提交 → 查询用户 → 校验密码哈希 → 写入 `session` → 跳转受保护页面。
        
    - 注意登录失败时的模糊提示策略（避免泄露“账号存在但密码错误”等敏感信息）。
        
- **第 23 天：登录状态保护与访问控制**
    
    - 编写自定义 `@login_required` 装饰器（或结合 `Flask-Login`），拦截未登录访问并重定向至登录页。
        
    - 处理 `next` 参数，登录后跳回用户原本想访问的页面。
        
- **第 24 天：退出登录与会话清理**
    
    - 实现 `/logout` 路由，清除 `session` 中的登录标识并给出退出提示。
        
- **第 25 天：常见登录表单安全隐患与排查**
    
    - 排查弱 `SECRET_KEY`、开放重定向（Open Redirect）、暴力尝试风险与 XSS/CSRF 防护盲点。
        
- **第 26 天：综合项目启动——需求拆解与数据库设计**
    
    - 规划“个人笔记 / 任务清单系统”，明确用户表与业务表关联及页面流转。
        
- **第 27 天：实现完整注册、登录、退出闭环**
    
    - 串联前端登录表单、后端校验、数据库查询与顶部导航栏动态状态切换（登录前显示“登录/注册”，登录后显示“用户名/退出”）。
        
- **第 28 天：实现登录后专属业务功能**
    
    - 绑定当前登录用户 ID，实现仅本人可见/可操作的增删改查功能。
        
- **第 29 天：边界测试、异常处理与代码重构**
    
    - 测试空提交、错误密码、未登录直访内页、刷新重复提交等场景，抽离重复逻辑。
        
- **第 30 天：课程复盘与进阶路线规划**
    
    - 梳理 30 天知识图谱，明确下一步可深入的方向（如邮件找回密码、OAuth 第三方登录、REST API / JWT、PostgreSQL 与部署上线）。
        

### 登录表单核心实现参考（第 21～22 天重点）

以 **Flask-WTF** 为例，一个规范的登录表单通常包含表单定义、路由校验与模板渲染三部分：

1. **表单类（`forms.py`）**：定义账号、密码与“记住我”字段及必填校验。
    
2. **登录路由（`routes.py`）**：通过 `form.validate_on_submit()` 判断合法提交，查询用户并用 `check_password_hash(user.password_hash, form.password.data)` 比对密码，验证通过后存入 `session` 并重定向。
    
3. **登录模板（`login.html`）**：渲染 `form.hidden_tag()`、各字段输入框、校验错误提示以及 `get_flashed_messages()` 全局提示。

### 数据库进阶与迁移工具（Database Migrations）

- **为什么加：** 目前有数据库和 CRUD 操作，但在实际开发中，数据库结构（表字段）经常需要修改。如果每次改表都要删掉重建，数据会丢失。因此必须引入 **Flask-Migrate**（基于 Alembic）来实现数据库版本的平滑迁移。
    
- **建议主题：**
    
    - `flask_数据库迁移管理`
### 日志记录与异常监控（Logging & Debugging）

- **为什么加：** 基础章节有“错误处理”，但在生产环境中，只靠前端报错页面不够，后端必须有规范的 **Logging** 模块来记录运行日志，方便排查线上问题。
    
- **建议主题：**
    
    - `flask_日志记录与调试技巧`
        

### 5. 项目实战与打包部署（Deployment & Production）

- **为什么加：** 学习 Flask 的最终目的是把项目跑在服务器上。光在本地用 `app.run()` 调试是不够的，初学者需要体验如何将应用部署到生产环境。
    
- **建议主题：**
    
    - `flask_综合项目实战`（串联前面的蓝图、数据库、登录）
        
    - `flask_生产环境部署`（如使用 Gunicorn + Nginx 或 Docker 部署的简要入门）
